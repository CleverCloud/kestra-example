# Deploy Kestra on Clever Cloud
[![Clever Cloud - PaaS](https://img.shields.io/badge/Clever%20Cloud-PaaS-orange)](https://clever-cloud.com)
[![Kestra.io - Workflow Orchestration](https://img.shields.io/badge/Kestra.io-Workflow%20Orchestration-blue)](https://kestra.io)

This repository deploys a self-hosted [Kestra](https://kestra.io/) instance on [Clever Cloud](https://clever-cloud.com), a European PaaS provider. Kestra is an event-driven, language-agnostic orchestration platform that lets you manage workflows declaratively in code, with hundreds of plugins to orchestrate business logic in any language – an alternative to Airflow or Rundeck.

The example runs Kestra **2.0 (LTS)** in standalone mode on the Clever Cloud **Linux runtime**, with **Java 25 (LTS)** installed by [mise](https://mise.jdx.dev). It uses a **PostgreSQL** add-on for the queue and repository, and a **Cellar** (S3-compatible) add-on for internal storage. The Kestra UI and API listen on port `8080`.

## How it works

The Linux runtime reads `mise.toml` and the `mise-tasks/` directory:

- `mise.toml` installs Java 25 (Temurin) and pins the Kestra version (`KESTRA_VERSION`) and the MinIO storage plugin version (`KESTRA_STORAGE_MINIO_VERSION`).
- `mise-tasks/build` is the build command. It creates the Cellar bucket with `s3cmd` if it does not exist yet, downloads the pinned Kestra executable from the [GitHub release](https://github.com/kestra-io/kestra/releases), verifies its SHA-256 checksum, and installs the `storage-minio` plugin.
- `mise-tasks/run` is the start command. It runs `kestra server standalone` with `config.yml`, giving the JVM 75% of the instance memory (override with the `JAVA_OPTS` environment variable).

`config.yml` wires Kestra to the add-ons through the environment variables Clever Cloud injects:

- **Queue and repository**: PostgreSQL (`POSTGRESQL_ADDON_*`). The connection pool is capped at 4 connections to fit small PostgreSQL plans.
- **Internal storage**: Cellar through the MinIO storage plugin (`CELLAR_ADDON_*`, `BUCKET_NAME`).
- **Basic authentication**: mandatory since Kestra 0.24, credentials from `BASIC_AUTH_USERNAME` (an email address) and `BASIC_AUTH_PASSWORD`.
- **Public URL**: `kestra.url` is built from `CC_DOMAIN`, so links generated by Kestra point to your domain.

Database migrations run automatically on startup (Kestra OSS behaviour).

```
.
├── config.yml          # Kestra configuration: PostgreSQL, Cellar storage, basic auth, URL
├── env.sh              # The deployment steps below as a script

├── mise-tasks/
│   ├── build           # Creates the bucket, downloads Kestra, installs the storage plugin
│   └── run             # Starts Kestra in standalone mode on port 8080
```

## Deployment steps

You need a [Clever Cloud](https://www.clever-cloud.com/) account, [Clever Tools](https://github.com/CleverCloud/clever-tools) installed and logged in, and `jq`. From the root of this repository, replace `<APP_NAME>`, `<EMAIL>` and `<PASSWORD>` with your own values:

```bash
# Create a Linux application (XS is the minimum, S or larger is recommended for real workloads)
clever create --type linux <APP_NAME>
clever scale --flavor XS

# Create the add-ons: PostgreSQL (XXS minimum, XS or larger recommended) and Cellar
clever addon create postgresql-addon --plan xxs_sml <APP_NAME>-pg
clever addon create cellar-addon <APP_NAME>-s3
clever service link-addon <APP_NAME>-pg
clever service link-addon <APP_NAME>-s3

# Bucket names must be unique and valid: derive it from the application ID
clever env set BUCKET_NAME "$(jq -r '.apps[0].app_id' .clever.json | tr '_' '-')"

# Public domain of the application, used for the links Kestra generates
clever env set CC_DOMAIN "$(clever domain | grep -o '[a-z0-9.-]*cleverapps.io' | head -1)"

# Basic authentication: the username must be an email address
clever env set BASIC_AUTH_USERNAME <EMAIL>
clever env set BASIC_AUTH_PASSWORD <PASSWORD>

clever deploy
clever open
```

If you add your own domain with `clever domain add <YOUR_DOMAIN_NAME>`, set `CC_DOMAIN` to it as well. Log in to the UI at `https://<your-domain>/` with the credentials you configured.

## Running locally

Kestra needs Java 25. To try it on your machine without the add-ons, download the same release and use the embedded H2 database and local storage:

```bash
mise install
curl -L -o kestra "https://github.com/kestra-io/kestra/releases/download/v2.0.4/kestra-2.0.4"
java -jar kestra server local
```

Then open http://localhost:8080 and follow the setup page to create your credentials.

## Script tasks and task runners

Docker is not available on Clever Cloud instances, so script tasks (Shell, Python, etc.) must use the **Process** task runner. Kestra 2.0 removed `kestra.plugins.defaults`, so this can no longer be set globally in `config.yml` with the open-source edition. Set it on each script task instead:

```yaml
- id: script
  type: io.kestra.plugin.scripts.shell.Commands
  taskRunner:
    type: io.kestra.plugin.core.runner.Process
  commands:
    - echo "Hello from Clever Cloud"
```

Script plugins are not bundled in this deployment: add `kestra plugins install` lines to `mise-tasks/build` for the ones you need, using versions compatible with your Kestra version.

## Troubleshooting

- Check the build and application logs: `clever logs`
- Check the environment variables: `clever env`
- Check that the add-ons are linked: `clever service`
- `Authentication required` (HTTP 401) on the API: send the basic auth credentials; the username must be an email address.
- The application is killed or restarts under load: Kestra is memory-intensive, scale up with `clever scale --flavor S` or larger.
- Database connection errors on small PostgreSQL plans: keep `maximum-pool-size` in `config.yml` below the plan's connection limit.
